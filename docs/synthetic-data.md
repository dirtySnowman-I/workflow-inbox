# Synthetic Data Plan

Workflow Inbox uses only fictional data.

No production records, customer information, private logs, credentials, scraped personal data, or data from previous projects will be used.

## Fictional Business

The demonstration represents a fictional company:

**Northstar Office Services**

The company handles office-maintenance requests.

## Request Data

Demo requests contain:

- requester
- summary
- status
- creation timestamp
- last-modification timestamp

Request IDs will be generated by the application.

## Example Request Data

The seed dataset may include records such as:

| Requester | Summary | Status |
| --- | --- | --- |
| Jordan Lee | Conference room projector is not working | NEW |
| Maya Chen | Replace broken office chair | IN_PROGRESS |
| Daniel Brooks | Repair kitchen faucet | DONE |
| Taylor Morgan | Air conditioner is leaking | NEW |
| Priya Shah | Replace damaged power strip | IN_PROGRESS |
| Alex Rivera | Meeting-room light is flickering | DONE |

All names and situations are fictional.

## Mock Integration Data

The fictional FormRelay integration uses deterministic synthetic event IDs.

Example:

```json
{
  "eventId": "evt_demo_001",
  "type": "request.created",
  "data": {
    "requester": "Taylor Morgan",
    "summary": "Air conditioner is leaking"
  }
}
```

Additional integration events may use:

- `evt_demo_002`
- `evt_demo_003`
- `evt_duplicate_test`

These IDs exist only for demonstrations and tests.

## Duplicate-Delivery Scenario

At least one mock FormRelay event will deliberately be delivered twice.

The expected behavior is:

1. first delivery creates the request;
2. the event ID is recorded;
3. second delivery is recognized as already processed;
4. no second request is created.

This allows the demo to show idempotent webhook handling without relying on a real third-party service.

## Dates and Timestamps

Seed data may use fixed timestamps so tests and demonstrations are reproducible.

No timestamps will come from private production systems.

## Credentials

No real external credentials are required.

If the mock webhook later uses an authentication token:

- the value will come from an environment variable;
- `.env` will not be committed;
- `.env.example` will contain only an obviously fake example.

## Rule

If a piece of data originated from a real private system, it does not belong in this repository.

When realistic examples are needed, create new fictional equivalents instead.
